# 阅读书目拍照识别录入 设计文档

> 版本：v1.1
> 日期：2026-11-05
> 状态：待确认（按反馈调整中）

---

## 一、背景与问题

### 1.1 现状

「📚 阅读书目」功能（`parent-panel.js` 的 `renderReadingBooksManagement`）目前只支持**纯手工录入**：每个语言列表下有一个 text input + 「添加」按钮，书名由家长逐字输入，存入 `readingBooks`（`{id,title,lang,finished}`）。

### 1.2 痛点

书多了以后，逐本手敲书名效率低、易拼错。家长希望**拍一张书封面/书脊，自动识别出书名并录入**。

### 1.3 已确认的约束（来自前期评估与本轮反馈）

- 项目是 **GitHub Pages 纯静态站点、无后端**，且用户偏好 **免费 + 离线优先** → OCR 选用 **Tesseract.js（浏览器端 WASM）**，完全免费、可完全离线。
- **中文包体积控制**：中文书封面识别需 `chi_sim` 语言包约 12MB，体积过大。本轮决定：**拍照 OCR 仅支持英文书**（只加载 `eng` 包 ~2.4MB），**中文书列表不提供拍照入口，仍走手工录入**（中文书数量通常少、且中文艺术字封面识别率本就一般，手工更可靠）。
- **交互化简 + 批量**：不再"逐本点选确认"，改为拍照后弹出**多行候选**（OCR 出的多行文字），每行带勾选框 + 全选，用户勾选一本或多本 → 一次「批量添加」录入。既减少操作步骤，又支持一张书架照录多本。
- 封面/书脊会带出版社、作者、副标题等干扰文字，纯前端无法 100% 精准判定，**形态定为「辅助录入（勾选确认）」**，而非全自动。

---

## 二、目标

在「阅读书目」页的**英文书列表**提供「📷 拍照/上传」入口：

1. 点按钮 → 调起相机或文件选择（`accept="image/*"`，手机 `capture` 调起相机）。
2. 选图后**本地离线 OCR**（仅 `eng`），不传任何服务器。
3. 识别文字拆成多行候选，弹「候选书名」勾选列表（默认全选，可取消/重选）。
4. 点「批量添加(N本)」→ 勾选项作为 `lang='en'` 书目一次性录入，走现有添加逻辑。
5. **中文书列表不显示拍照按钮**，仅保留手工录入（规避中文包体积）。
6. 全程不影响现有手工 text 输入（保留兜底）。

## 三、技术方案

### 3.1 OCR 引擎：Tesseract.js（本地化离线，仅英文）

- 通过 npm 安装 `tesseract.js`，取其 `dist/` 产物本地化到 `js/lib/tesseract/`：
  - `tesseract.min.js`（UMD 核心）
  - `worker.min.js`、`tesseract-core.wasm.js`、`tesseract-core-simd.wasm.js`（及对应 `.wasm.gz`）
  - 语言数据 **仅 `eng.traineddata.gz`** → `js/lib/tesseract/lang/`（**不引入 chi_sim**）
- 初始化时显式指定本地路径，确保**完全离线**：
  ```js
  Tesseract.recognize(image, 'eng', {
    workerPath: 'js/lib/tesseract/worker.min.js',
    corePath:   'js/lib/tesseract/',
    langPath:   'js/lib/tesseract/lang/'
  })
  ```
- **动态加载**：`tesseract.min.js` 不在 `index.html` 常驻，用户首次点「拍照」时才动态注入 `<script>`（已加载则跳过），**不拖慢首屏**。

### 3.2 语言包策略（体积已最小化）

| 语言包 | 体积(约) | 加载时机 |
|--------|---------|---------|
| `eng`  | ~2.4MB  | 首次拍照识别英文书时加载并缓存（仅此一个） |

**不引入 `chi_sim`**，中文书完全不触发 OCR，零中文包体积负担。GitHub Pages 承载 2.4MB 静态资源无压力。

### 3.3 候选提取与批量勾选

`Tesseract.recognize` 返回 `data.lines`（按行）。方案：
- 优先用 `data.lines` 每行 `text` 作为候选；
- 过滤过短（<2 字符）、纯标点/纯数字行；
- 候选列表**每行一个 checkbox**（默认全选）+ 顶部「全选/取消」+ 底部「批量添加(N本)」按钮 + 「✍️ 手动输入」兜底项；
- 勾选 1 本即单本录入，勾多本即批量录入，一步到位。

### 3.4 复用现有 UI 模式

- 候选弹窗**复用项目成熟 `overlay` 模式**（`parent-panel.js` 中大量使用的 `className='overlay'` + 点击遮罩关闭），不新增弹窗组件。
- 录入逻辑**复用现有添加逻辑**：对勾选的每本书 `readingBooks.push({id,title,lang:'en',finished:false})` + 一次 `store.set` + 重渲染。

## 四、UI 改动

在 `renderReadingBooksManagement` 的 `renderBookList` 中：

- **英文书列表**（`lang==='en'`）：「添加」行旁新增「📷 拍照/上传」按钮：
  ```
  [ 输入书名…… ] [添加]  [📷]
  ```
- **中文书列表**（`lang==='cn'`）：**不显示**拍照按钮（保留手工录入），可在该列表下方加一行小字提示「中文书请手动输入书名」。

- 英文「📷」点击流程：`openBookOcr()`（无 lang 参数，固定英文）：
  1. 动态确保 tesseract 已加载（未加载则注入脚本，带超时兜底）。
  2. 触发隐藏 `<input type="file" accept="image/*" capture="environment">`。
  3. 选图后显示「识别中…」（用 `logger` 进度回调，可放 overlay 内）。
  4. 识别完成 → 渲染**候选勾选 overlay**（多行 checkbox + 全选 + 批量添加）。
  5. 点「批量添加」→ 调现有添加逻辑录入勾选项 → 关闭 overlay → 重渲染列表。
- **降级**：tesseract 加载失败 / 资源缺失 / 识别无结果 → 提示并聚焦手工输入框，绝不阻塞录入。

## 六、识别准确率预期与降级

- **英文书名**（拉丁字母、印刷体）：识别率较高，候选基本能命中，批量勾选体验好。
- **中文书**：不做 OCR，仍手工录入（规避 12MB 中文包 + 中文艺术字识别率一般）。
- **兜底闭环**：任何环节失败都回到「手工输入」，功能永远可用。

## 七、实施步骤（确认后执行）

1. `npm i tesseract.js` → 拷贝 dist 资源到 `js/lib/tesseract/`（**只拷 eng 语言包**）。
2. `parent-panel.js`：英文列表加「📷」按钮 + `openBookOcr()`（动态加载库 / 文件选择 / 识别 / 候选勾选 overlay / 批量录入）；中文列表隐藏拍照按钮 + 提示文案。
3. `css/parent.css`：按钮与候选弹窗样式。
4. `node --check` 全量语法校验。
5. 同步 `monster-pet/` 子目录。
6. 用 Playwright 无头截图验证（用户远程看不到桌面）：注入含多本英文书的测试图 → 走识别 → 候选勾选 → 批量录入，截图确认。

## 八、防回退 / 风险

- 动态加载失败必须兜底到手工输入，不能让「拍照」入口变成死按钮。
- 不改变 `readingBooks` 数据结构，不影响每日阅读轮转等既有逻辑。
- 体积：仅 `eng` 包随首次拍照加载（~2.4MB），无中文包负担。
- 同步 `monster-pet/` 子目录（历史多次因漏同步导致线上看不到改动）。
